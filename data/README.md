# Example data — VILPE Sense demo site

Dataset for the VILPE Vantaa demo building ("VILPE Express Store" / site
"VILPE Hallin katto, Vantaa"). Produced by pulling everything from the
unauthenticated public API behind the `sense.vilpe.com/public/*` share
links, stdlib only:

```bash
python scripts/fetch_sense_data.py data                    # site + fans + sensors + layout
python scripts/fetch_sense_data.py data --sensor-history   # + 12 h sensor history (~730 req)
```

API base: `https://tdqn5whm3k.execute-api.eu-west-1.amazonaws.com/prod`

- `GET /roofs/public/{site_link}` — site, devices, sensors, layout, value sets
- `GET /roofs/public/{site_link}?valueSetId={id}` — sensor readings at a snapshot
- `GET /roofs/public/{site_link}/presigned-layout-url` — layout image URL
- `GET /public-measurements/{device_link}/{start}/{end}` — full device history
  (start/end are ignored; it always returns everything)

Timestamps: API-sourced files are **UTC** (`...Z`); the zip-derived
`readings/sensors.csv` is naive **Europe/Helsinki** local time.

## Layout

| File | Contents |
| --- | --- |
| `site.json` | Site metadata: Finnish description, public links, gateway, layout info, value-set summary |
| `site-layout.png` / `.pdf` | Roof plan (PNG from the API, PDF from the original Drive zip); gitignored, PNG regenerated by the fetch script |
| `devices.json` | The 7 VILPE MCU-2 ventilation fans: serial, location, transmitters, layout coordinates, latest values, public link |
| `sensors.json` | The 51 VILPE RHT-2 environmental sensors: id ↔ serial, layout coordinates, latest readings |
| `readings/fans/<device-id>.csv` | Per-fan time series, ~10 600 rows each, 2025-05 → now |
| `readings/sensors.csv` | Sensor readings from the zip export, 37 303 rows, 2025-09 → 2026-09 (hourly) |
| `readings/sensor-snapshots.csv` | Optional `--sensor-history` output: per-sensor T/RH at each 12 h value set |

## CSV schemas

`readings/fans/*.csv` — union of each fan's API `valueTypes` (each series
has its own timestamps, so cells are sparse):

```
timestamp, rpm, mold_index,
indoor_temp_c, indoor_rh_pct, indoor_abs_humidity_g_m3,
outdoor_temp_c, outdoor_rh_pct, outdoor_abs_humidity_g_m3
```

`indoor_*` = the fan's indoor (structure-side) RHT-1 transmitter,
`outdoor_*` = outdoor reference. `mold_index` is VILPE's computed mold-risk
index (only present from 2026-03 onward). `*_abs_humidity_g_m3` is computed
from T+RH (Magnus formula) — the API doesn't expose it directly.

`readings/sensors.csv` (zip-derived):

```
timestamp, sensor_id, sensor_serial,
base_station_id, base_station_serial,
temperature_c, relative_humidity_pct, absolute_humidity_g_m3
```

## Notes

- The 51 RHT-2 sensors sit on the roof as a humidity-measurement grid —
  `coordinates` in `sensors.json`/`devices.json` place every device on
  `site-layout.png` (calibration factor in `site.json`).
- The API exposes finer and longer data than the zip: fan histories run to
  "now" and include `mold_index`, which the export only had as a latest value.
- Per-sensor history is only public via 12-hourly value-set snapshots
  (`--sensor-history`); the hourly `readings/sensors.csv` exists only in the
  zip export.
